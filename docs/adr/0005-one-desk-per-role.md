# One integration branch, one desk and one name per Role

A single shared `office/integration` branch made every review a mixed diff: an Ansible playbook, a Go domain package and a set of HTML templates arriving as one pile, read in one frame of mind, and merged as one decision. Each Role now gets its own integration branch, `<integration_branch_prefix><role-slug>`, and its Workers branch from that one. A reviewer opens `integration/ops` knowing they are reading ops, and a design delivery cannot be blocked by an unrelated ops conflict.

The branch reaches the default branch only through `review-integration.sh`. Where Plannotator is installed, that script opens a review session on that one branch and merges **only** on an explicit approval: the approval is the human merge authority, exercised in a UI instead of on a shell prompt. Where it is not installed, the script says so and stops - a missing tool degrades to the manual review the office had before it, never to an unreviewed merge.

A Role is also a **person**: a `name` and a `title`, both required by the config. The pair names the Role's standing worktree, its delivery branch and its Orca display name, so the app lists `Jim (Platform Engineer)` where it used to list `role-platform-09`. That old label was a worktree counter, not an identity: it told a reviewer nothing except how many times the office had run, and it implied a fleet of platform Workers where there is exactly one Role.

The counter disappeared because the worktree is now durable. `prepare-worktrees.sh` creates each Role's desk once and reuses it every cycle, fast-forwarding it onto the Role's integration branch when it is clean and refusing to touch it when it is dirty or still holds an unlanded delivery. One desk per Role is the same invariant as one writer per path ([ADR 0002](./0002-one-writer-per-path.md)) seen from the other side: two worktrees for one Role are two branches over one write set, and the second delivery is born in conflict.

The cost is that a Worker is dispatched into an existing worktree, where Orca rejects every creation flag (`--name`, `--base-branch`, `--display-name`, `--setup`). Placing the desk on the right branch is therefore a step of the cycle rather than an argument of the dispatch. That is the right place for it: the Coordinator can report a desk it refuses to prepare, while a rejected flag would only fail a dispatch.
